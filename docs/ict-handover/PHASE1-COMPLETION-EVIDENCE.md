## Prosedur QA dalaman

1. Gunakan cabang Issue #68 dan PostgreSQL loopback kosong bernama `staylink_issue62_personal_completion<sesi>_test`. Guna [templat Linux HTTPS](../../deploy/demo/README.md) dan fail env privat. Untuk larian CLI set `APP_ORIGIN=https://localhost:5444` dengan hos sintetik dan Mailpit loopback. Ujian ini boleh berjalan tanpa Cloudflare.
2. Jalankan `npm ci`, `npm run db:generate` dan `npm run build`. Periksa kosong dengan `node scripts/uat-preflight.mjs empty`, jalankan `npm run db:test:migrate`, `npm run db:seed` dan `npm run db:uat-demo`. Simpan direktori kit mod 0700. Julat ujian hanya menggunakan alamat `@example.test` dan penyelesaian pembayaran tiruan.
3. Gunakan `bash scripts/rehearse-demo-host.sh "$KIT/portal.env" --completion`. Ia memeriksa kit, menjalankan integrasi hingga tutup, menghidupkan pelayan HTTPS setempat untuk Playwright, dan menghentikan pelayan selepas ujian. Kadar 1234 sen dalam skrip ialah nilai ujian sahaja. Untuk ujian manual di masa hadapan, simpan nilai latihan yang dipilih dalam env privat. Nilai itu bukan konfigurasi produksi.
4. Urutan lakonan ialah pemohon → PIC → PPSK dan bayaran pertama → PIC merujuk → dua jabatan memberi ulasan → PIC menyerah KP → Urus Setia merekod keputusan bercampur → Penandatangan menerbitkan versi latihan → pemohon menjawab TANGGUH → PIC dan PPSK menyemak → rujukan terpilih dan keputusan susulan → invois kedua tiruan dan rekonsiliasi → PPSK menutup. Unit yang masih TANGGUH atau SKB belum muktamad. Penolakan akses, versi lapuk dan surat induk yang kekal perlu diperiksa.
5. Selepas ujian, gunakan [pemulihan sintetik](../../scripts/rehearse-synthetic-restore.sh) ke DB kosong lain. Rekod pemeriksaan termasuk semakan cap jari acara `SYNTHETIC_PORTAL_COMPLETION` melalui audit sintetik, snapshot, bukti, invois serta notifikasi. Kit dan stor data tidak disertakan dalam artifak semakan.

## Keputusan yang memerlukan pemilik atau JTIK/Kewangan

- **Jabatan Bangunan dan Unit Rekod** mengesahkan dokumen yang diperlukan bagi susulan TANGGUH/SKB, tindakan apabila tarikh keputusan terlepas, reka bentuk KP dan surat rasmi, kuasa menandatangani, penutupan/pembukaan semula, arkib dan retensi. Kekalkan rujukan dan akuan di bawah cadangan MBSP-01 hingga MBSP-08 sehingga dimuktamadkan.
- **JTIK dan Kewangan** meluluskan peluasan kepada sandbox MBSPPay dan menyediakan spesifikasi identiti invois, kadar, kaedah pengesahan callback, lejar dan aturan rekonsiliasi/refund. Adapter latihan kekal terasing.
- **JTIK** menyediakan akses Oracle 19.30 SE2 ke PDB latihan, maklumat kuota dan akaun pemasangan/runtime minimum. Jaminan Oracle Free 23 terpakai kepada makmal sahaja. Ujian semua peranan terhadap Oracle dan pengesahan cutover masih belum lengkap.
